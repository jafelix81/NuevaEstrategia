# Phase 146 — IvyDB US OI strict PIT boundary and continuity correction

**Date:** 2026-11-06  
**Input:** Code review of the Phase 145 receipt-aware OI helper and its 15-test regression suite.  
**Mode:** Fail-closed implementation audit only. No licensed raw IvyDB sample, vendor contact, purchase, forward-return test or production change.

## Decision

**Correct three boundary/continuity defects before any real IvyDB OI panel is admitted.** The Phase 145 helper's design was directionally conservative, but its implementation still allowed an exact-timestamp feature and could calculate a nominal one-session change from a stale prior observation when an intervening observation was present.

## Findings and corrections

1. **Equal knowledge/decision timestamps were accepted.** `features_known_by` used `known <= decision`. The helper stores no intra-timestamp event sequence, so equality does not prove the file arrived before the decision was made. Eligibility now requires strict `known < decision`. A regression test confirms exact equality is excluded while a later decision instant remains eligible.
2. **A stale previous session could be used.** The caller supplies the exchange-calendar `previous_session_date`. If an older row existed and the declared previous date skipped an intervening session already present in the same contract panel, the old code still calculated a multi-session ΔOI as if it were one session. The helper now emits `NON_ADJACENT_PREVIOUS_SESSION` and suppresses the delta whenever an intervening contract observation exists.
3. **Expiration-date continuity was implicit.** The helper compared a terms fingerprint but did not separately require the expiration date to remain identical. It now emits `EXPIRATION_DATE_BREAK` when the paired observations disagree, even if the supplied terms key was accidentally unchanged.

The regression suite increases from 15 to **18 tests**. The existing positive/negative ΔOI, missing-session, receipt provenance, timezone, expiry-session, duplicate, zero-denominator and input-order tests remain intact.

## Remaining limitations

- The helper still accepts one immutable source version per contract/session. It is not a correction-vintage event store. Original delivery and each later patch must be stored as separate immutable versions upstream; a corrected value must never be backdated.
- The helper cannot independently verify that `previous_session_date` came from the correct exchange calendar. That date must be generated by a validated calendar and the input panel must retain missing-session diagnostics.
- No actual IvyDB file, historical first-receipt log, patch-vintage archive or optionable-universe coverage sample is available. The source remains conditional and historical backfill is not strict PIT-approved.
- ΔOI remains net contract state, not buyer direction, gross opening volume, aggressor flow or beneficial-owner identity.

## Validation and disposition

The PR-only regression workflow compiles the helper and runs the complete offline suite. No network data are downloaded. The hosted run is the final validation gate.

No forward returns, feature selection, bootstrap/LOO, final holdout or alpha inference were performed. No vendor contact, trial, purchase or terms acceptance occurred. No production change was made.
